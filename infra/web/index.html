The authority model

The system is designed as repeated negotiation rather than polling. The audience contributes; the algorithm aggregates; the performer remains able to intervene.

Audience input
Parameter bus
Weighted consensus

Artistic output

Consensus components

  • Spatial: distance from a declared stage position.
  • Temporal: age relative to an explicit evaluation clock.
  • Agreement: the proportion of nearby values in the current cohort.
  • Filtering: weighted deviation and optional outlier removal.
  • Smoothing: interpolation from a prior value.

Performer modes

  • Absolute: replace the computed value.
  • Blend: combine performer and audience values.
  • Lock: hold a performer-selected value.
Design is not outcome. These mechanisms make authority explicit in source code. Whether they are understandable, fair, usable, or artistically productive requires separate study.

A benchmark with a narrow name

The benchmark times only one in-process function. It is designed to produce evidence, not a marketing number.

Explicit exclusions

  • network transport and clock synchronization;
  • serialization and Socket.IO;
  • Redis, OSC, rendering, and synthesis;
  • audience-device latency;
  • delivery and error rates;
  • connection capacity;
  • rehearsal and live-performance behavior.
Permitted future wording A preserved result may be called “in-process consensus compute time in the recorded environment.” It cannot be relabeled as end-to-end audience latency.
